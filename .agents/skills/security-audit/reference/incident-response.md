# Runbook: атака уже идёт

Когда пользователь говорит «балансы странные», «кто-то вывел много», «зачисляют фейковые депозиты» — порядок жёстко такой. Сначала остановить утечку, потом разбираться.

---

## 0. Не удаляй улики

Перед любыми правками:
```bash
cp bot.js bot.js.incident-$(date +%s).bak
cp -r . ./incident-backup-$(date +%s)      # включая state.json / stats, если есть
```
`bets_monitor` пишет статистику в файл — **не обнуляй её**, это твой журнал атаки.

---

## 1. Остановить утечку (минуты, не часы)

Выбери минимальное вмешательство, которое закрывает кран:

| Что происходит | Немедленное действие |
|---|---|
| **Боевой ключ платёжки найден в публичном репо** | **Ротация ключей в ЛК провайдера — первым действием, до всего остального.** Параллельно выгрузить историю транзакций за период с момента коммита и сверить с заявками в боте |
| Массовая накрутка баланса через `/api/record-bet` / `/api/sync-balance` | Закрыть эндпоинты на входе: `return send(503, { error: 'maintenance' })` — игра временно доступна только для чтения |
| Фейковые депозиты через вебхук | **Ротировать секрет** у платёжки и в env, затем поставить проверку подписи |
| Аномальные выводы одобрены | Остановить `processOrderAction` (аппрув) до разбора; отозвать/придержать уже ушедшие переводы, если банк позволяет |
| Кто-то получил админку | Задать явный `ADMIN_ID` в env и перезапустить; сменить `BOT_TOKEN` через BotFather |

Команда для быстрого отключения одного маршрута (в начало ветки):
```js
if (url.pathname === '/api/sync-balance') return send(503, { error: 'temporarily disabled' });
```

**Ротация секретов** (если подозреваешь утечку): `BOT_TOKEN` (BotFather → /revoke), `PLATEGA_SECRET`, `HELEKET_API_KEY`, `COINSO_SECRET_KEY`, `PAYMENT_WEBHOOK_SECRET`. После ротации `BOT_TOKEN` все выданные `initData` становятся недействительными — это ожидаемо.

---

## 2. Собрать доказательства

```bash
# кто и сколько накрутил
grep -iE "flagSuspicious|АНТИЧИТ|Попытка ручной накрутки|Подмена суммы" bot.log | tail -200

# зачисления депозитов подозрительно быстро после регистрации
grep -iE "Успешное зачисление|Авто-зачисление" bot.log | tail -200

# доступы в админку
grep -iE "Попытка доступа в админку|Доступ запрещён" bot.log | tail -100
```

Через `bets_monitor.getPlayerDossier(userId, user)` — досье по игроку. Зафиксируй по каждому подозреваемому: `userId`, `username`, время, суммы, метод, реквизиты вывода, IP (если логируешь).

**Признаки, которые почти всегда означают эксплойт, а не удачу:**
- первый вывод в течение часов после первого депозита;
- баланс вырос без записи в `bets_monitor.recordBet`;
- один `initData` с разных IP; много аккаунтов на один реферальный код;
- вывод ровно на сумму, покрывающую накрученный баланс;
- заявки created пачкой с одного IP.

## 3. Локализовать вектор

Ответь письменно на три вопроса — это и есть отчёт об инциденте:
1. **Как вошли?** (какой эндпоинт, какая отсутствующая/обойдённая проверка)
2. **Что получили?** (сумма накрутки, сумма вывода, статус заявок)
3. **Когда началось?** (таймстемп первых аномальных записей)

Если вектор не ясен — **не перезапускай прод**, пока не поймёшь: рестарт обнулит `Map()` с балансами и заявками и уничтожит состояние, по которому можно считать ущерб.

---

## 4. Оценить ущерб

Помни конверсию: **10 ⬦ = 1 ₽**.
Считай по трём категориям:
- **Выведено и оплачено** — прямая потеря. Заявки со статусом «выплачено» от скомпрометированных аккаунтов.
- **В процессе** — заявки `pending`. Их можно **отклонить** (`processOrderAction(..., 'reject')`), вернув токены; это остановимая потеря.
- **Накручено, но не выведено** — не потеря, но требует сброса баланса.

---

## 5. Закрыть вектор и вернуть доверие

1. Применить фикс по `reference/fix-patterns.md` (начиная с P0).
2. **Сбросить скомпрометированные балансы** — только после того, как вектор закрыт, иначе накрутят снова:
```js
for (const [id, u] of users.entries()) {
  if (suspicious.has(id)) { u.tokens = START_TOKENS; u.staked = 0; u.stakeSince = 0; u.accruedBase = 0; }
}
```
3. Уведомить пострадавших, если задеты честные игроки (ложные срабатывания бывают — сверяй досье, а не только флаг).
4. Добавить регрессионный PoC в `scripts/`, чтобы вектор нельзя было вернуть случайно.
5. Записать инцидент в `reference/known-findings.md` со статусом и датой.

---

## 6. Что делать ПОСЛЕ (чтобы не повторилось)

- Прогнать `SKILL.md` целиком заново — атака почти всегда использует не один, а два-три слабых места.
- Проверить, что `flagSuspicious` **реально** доходит до админа, а не теряется в `.catch(() => {})`.
- Ввести холд на первый вывод (24–72 ч) и суточный лимит вывода на аккаунт.
- Если возможно, перейти на автозачисление **только** от платёжки с подписью, а SMS/ручное подтверждение оставить как вспомогательный канал **с проверкой админом**.

---

## Правила поведения во время инцидента

- Сначала остановить утечку публично (пользователи могут заметить перерыв в работе — это нормально), потом молча расследовать.
- Не удалять и не «причёсывать» данные.
- Не обвинять игрока без досье: ложные срабатывания античита бывают, а сброс баланса честному игроку стоит репутации.
- Все числа ущерба — в рублях и токенах, со ссылкой на источник (лог/запись).
