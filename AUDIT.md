## 2. Текущая экономика

**Апгрейд** (`upgrade.js`, `bot.js:2706`):
- Шанс: `chance = min(chanceCap, (1 − edge) × source / target)`. Ожидаемое значение = `−edge × source`, то есть касса всегда в плюсе.
- Источник — токены или предмет из инвентаря, списывается атомарно (`db.atomicUpgradeRun`).
- Результат бросает сервер (`rnd01()`, `bot.js:2760`). Клиент шанс не определяет.
- Идемпотентность: `requestId` в `upgrade_runs`, повтор возвращает сохранённый результат (`bot.js:2719`).
- Тесты: `test-upgrade-math.js` — 236 проверок, все проходят.

**Кейсы** (`bot.js:2590`, `db.js:571`):
- Открытие стоит токенов (`price`), списание атомарно в `atomicOpenCase`.
- Токены покупаются за реальные деньги (Coinso, Platega, Stars). То есть **кейсы платные**. По правилам этапа 5 их нельзя расширять без подтверждения.
- Шансы — веса `w` в `items.js` / `case-modes.js`, сумма 100 на режим, в коде видны.
- Возврат игроку 0.82–0.86, проверяется в `test-upgrade-math.js`.
- Тест-прокрут (`/api/cases/warmup`) не списывает токены и даёт балл прогрева, который учитывается при следующем открытии.

**Баланс**: `users.tokens` меняется только через транзакции в `db.js` и пишется в `ledger`. Инвариант проверяется в `test-new-features-e2e.js` (opening + SUM(ledger) = баланс).

### 3.2. Безопасность (проверено по коду)

- **initData (Telegram)**: HMAC-SHA256 с `WebAppData` и `BOT_TOKEN`, `bot.js:866–867`. Ок.
- **Coinso-вебхук**: проверка `X-Signature` через HMAC, `bot.js:1912–1924`. Ок, отсутствующая или неверная подпись дают 403.
- **Апгрейд и кейсы**: сервер определяет шанс, результат и цену. Клиент шлёт только `mode`, `targets`, `amount`/`itemId`, `requestId`. Ок.
- **Лимиты**: `checkRateLimit` на каждый эндпоинт, `bot.js:2707`, `2591`, `2550`. Ок.
- **Админ-данные**: проверка роли должна быть на сервере. Отдельный аудит этого не делался. **Не проверено** (см. раздел 5).
- **Секреты в клиенте**: поиск по `index.html` и `public/` не выполнялся (в этапе 8 будет).

### 3.3. Регрессионные риски для последующих этапов

- `index.html` и `public/index.html` должны совпадать. Меняем корневой файл, затем `npm run sync:frontend`, иначе `check:frontend` упадёт.
- `assets/case-modes.js` и `public/assets/case-modes.js` тоже должны совпадать.
- Цены режимов кейсов меняются только в `assets/case-modes.js`, иначе падает `test-upgrade-math.js`.
