## Волна 2026-10-19/20 — Case Hub, Upgrade Arena, идемпотентность

Базовая линия: `5a86c3e` (`main`), ветка `feat/case-modes-upgrade`.

### Новые механики

- **Case Hub**: все 20 кейсов в одном разделе — 15 классических из `items.js`
  и 5 режимов (`STARTER DROP`, `CYBER RUSH`, `GOLDEN VAULT`, `GLITCH MODE`,
  `OMEGA CORE`) из `assets/case-modes.js`; у каждого кейса обложка
  `assets/cases/<id>.jpg`. Сохранены рулетка, инвентарь, продажа, апгрейд,
  бесплатный кейс и кейс за 5 друзей. Открытие: `POST /api/cases/open`,
  цена/дроп/шансы — серверные, запись в `case_opens` и `game_rounds`,
  предмет — в `user_inventory`.
- **Upgrade Arena**: `POST /api/upgrade/run` (одиночный/мульти),
  `POST /api/upgrade/ladder/{start,step,cashout,state}` (3/5/10 шагов),
  `POST /api/upgrade/catalog`, `POST /api/upgrade/history`.
  Шанс: `min(cap, (1 − edge) × S / T)`; мульти: среднее шансов, без двойного
  учёта; режимы SAFE/BALANCED/EXTREME различаются edge/потолком/cap.
- Серия на клиенте — последовательность серверных раундов, каждый со своим
  `requestId`; при ошибке серия останавливается и баланс сверяется.
- У каждого кейса — обложка `assets/cases/<id>.jpg` (генератор
  `tools/generate-case-covers.py`), без эмодзи вместо иконки. В карточках
  сохранён зелёный индикатор «онлайн» слева от текста.
- Рефералы перенесены из отдельного экрана в профиль (`#profileRef`):
  навигация стала 4-раздельной, код/ссылка/статистика/15 % сохранены.
- Из интерфейса, README и конфига новых кейсов убраны служебные показатели экономики; игроку показываются только цена, состав и шансы.

### Ограничения

- Сессии «Револьвера» остаются in-memory (как и раньше): после рестарта
  сервера активный раунд теряется. Лесенка и кейсы — в SQLite/Turso.
- Оффлайн-демо (`IS_TG=false`) использует локальный RNG; это явно демо-режим,
  реальный баланс недоступен.
- `ui-test.js`/`tg-test.js` по-прежнему написаны под старую вёрстку; вместо них
  добавлен актуальный `test-frontend-smoke.js`.

## Осталось до merge

- Финансовый flow `депозит -> баланс -> реферальная выплата` не объединён в одну общую БД-транзакцию; сейчас используются отдельные атомарные операции и persistent claims.
- Анти-самореферал по отпечатку реквизитов/IP/устройства не реализован: соответствующие данные не заведены в схему.
- В репозитории не найден отдельный accept-duel HTTP endpoint; реализованного атомарного accept API также нет. Есть только `createDuel`, `settleDuel`, `cancelDuel`.
- В `index.html` остаются динамические `innerHTML` и клиентские `Math.random` в игровых/денежных сценариях; полный перенос расчётов на сервер не выполнен.
- Полный HTTP smoke-набор с реальными webhook-конкурентами не запускался.

PR остаётся draft с пометкой `DO NOT MERGE` до устранения перечисленных ограничений.
