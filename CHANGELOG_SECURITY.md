# Security changelog

## Исправлено в security-fixes-2026-10

- Восстановлены полноценные версии `bot.js`, `db.js`, `turso.js` из main/локального security-набора вместо 44–47-байтных заглушек; после публикации требуется сверка SHA/размера через GitHub.
- Схема содержит идемпотентные `processed_payments` и `referral_payouts` с уникальными ключами; текущий flow `creditDeposit` всё ещё требует переноса платежа, баланса и реферальной выплаты в одну SQLite/Turso-транзакцию.
- Free-case выполняется через условное списание и транзакцию локальной БД.
- Серверные случайные значения для игр/сейфа используют crypto; клиентский `Math.random` в UI и широкое использование `innerHTML` ещё требуют рефакторинга.
- Добавлена миграция `tools/init-turso.js` для cooldown, self-referral fingerprints и платёжных идемпотентных таблиц.
- Секреты не читаются из `.env`; локальные статистические файлы и патчи исключены из `.gitignore`.

## Не завершено / требует отдельного исправляющего коммита

- Полная единая транзакция платёж → баланс → referral 15% (включая rollback при ошибке и persistent webhook claim) не завершена.
- Сравнение хешей платёжных реквизитов/IP/device и блокировка self-referral в production flow не подключены к депозитам.
- Эндпоинт атомарного принятия дуэли не найден в `bot.js`; доступны create/settle/cancel DB-операции, но accept flow со списанием обеих ставок отсутствует.
- Полная синхронизация новых таблиц/колонок в `turso.js` и подтверждение queue retry semantics не завершены.
- `index.html` содержит оставшиеся `innerHTML` и клиентский `Math.random`; `tg_block.js` содержит пользовательские HTML-строки, требующие отдельного DOM-safe рефакторинга.
- Smoke-тесты требуемых гонок/идемпотентности и `npm audit` не выполнены в этом коммите.

PR #6 оставлен draft с заголовком `DO NOT MERGE`: восстановление крупных исходников и полная GitHub-сверка ещё не подтверждены.
