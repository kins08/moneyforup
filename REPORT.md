## 5. Оставшиеся ограничения и риски

1. **Визуал на 360px не проверен в браузере.** Headless-Chrome в этом окружении не создаёт скриншот. `test-mobile-360.js` — статическая проверка CSS, а не рендер. Нужна ручная проверка на устройстве.
2. **Таймеры при размонтировании.** В коде Pulse, Trend и апгрейда очистка есть (`return ()=>{ dead=true; clearInterval(timer); }`), но не проверена в браузере после ухода с экрана.
3. **Число проверок `test-new-features-e2e.js` плавает (110–114).** Часть проверок зависит от времени. Падений нет, но точная цифра нестабильна.
4. **Двойной клик в апгрейде проверен слабо.** Тест `test-regression.js` утверждает «не списано больше ставки», а не «списано ровно одна». Точное утверждение требует отдельного сценария.
5. **Локальные изменения баланса в других играх.** В `index.html` при поиске `S.balance` видны изменения в ракетке, колесе, кейсах, профиле и др. (строки около 1793–9865). A2–A4 касались только апгрейда и лесенки. Остальные игры — отдельный аудит, который не входил в AUDIT.md.
6. **Pulse и Trend: демо-режим без Telegram.** Ставки не проводятся, это сделано намеренно (баланс только на сервере). Визуальная часть демо не проверялась в браузере.
7. **Прогрессия: сезон.** Дата старта сезона (1 октября 2026, UTC) зашита в `bot.js`. Её нужно согласовать.
8. **Экономика Pulse и Trend не подтверждена реальными данными.** RTP 92% — расчёт и симуляция (`test-pulse.js`, `test-trend.js`), а не данные от игроков. Перед запуском стоит прогнать `tools/simulate-rtp.js`-подобную симуляцию на реальном распределении ставок.
9. **Pulse: серверный seed хранится в памяти процесса.** При перезапуске сервера открытые раунды теряются (списанные ставки останутся без результата). Это ограничение текущей архитектуры; схему БД по правилам не меняли. Вариант решения — хранить seed в `game_rounds` — требует подтверждения (правило «схема БД без согласования»).

## 6. Инструкция локального запуска

Требования: Node.js >= 22.13 (проверено на v24.21.0), npm.

```
npm install
npm run check:syntax        # синтаксис ключевых модулей
npm run check:frontend      # index.html и public/index.html идентичны
npm run test:new            # апгрейд, e2e, Pulse, Trend, прогресс
node test-regression.js     # регрессия: админ-доступ, двойной клик, секреты
node test-frontend-smoke.js # фронтенд в jsdom
npm start                   # запуск бота (нужны переменные окружения)
```

Переменные окружения (значения секретов не указываются): `BOT_TOKEN`, `PUBLIC_URL`, `APP_URL`, `ADMIN_ID`, `PAYMENT_WEBHOOK_SECRET`, `COINSO_MERCHANT_ID`, `COINSO_API_KEY`, `COINSO_SECRET_KEY`. Список — в `.env.example`.
